# /industry-analysis：產業深度分析

**用法：** `/industry-analysis [產業名稱或主題]`

**觸發時機：** 董事長或 CEO 要求分析一個產業的結構性機會或風險時。輸出 MDX 報告，推上 GitHub。

**跳過時機：** 個股財報細節（交給 earnings-analyst）、技術前沿預測（交給 CTO）、純宏觀 Regime 判讀（交給 CMO）。

---

## 核心問題

每份分析必須回答三個問題，缺一不補：

> **為什麼現在？** 什麼結構性變化讓這個機會剛剛打開或即將關閉？
> **為什麼是它？** 哪家公司佔據了最難被取代的位置？
> **什麼會讓邏輯失效？** Kill Switch 何時觸發？

---

## 數字標注規則（強制執行）

引用任何具體數字，必須在數值後緊接標注來源類型，三選一：

- `[實時查詢]`：當場 WebSearch/WebFetch 所得
- `[訓練資料，時效需確認]`：來自訓練資料，可能已過時
- `[假設設定]`：分析者主動設定的情境參數

**未標注的具體數字自動違規。** 若無法補標，改用方向性描述（「偏高」「加速成長」）替代，不得裸引數字。

## 前置：讀入 Xompass 現有資料

執行分析前，**必須先讀取以下三類資料**，融入分析而非重複列出：

### A. 讀取當前 Regime
```
data/regime/current.json
```
- 確認分析產業是否在 `focus_sectors` 或 `suppress_sectors` 名單內
- 若在 suppress_sectors → 加 ⚠️ 標注：「當前 Regime 壓制此板塊，需說明反向理由」
- 取 `bible_anchor` 中的長期利率路徑假設，用於估值部分

### B. 讀取現有 Insights
```
data/insights/insights.json
```
- 取所有 `status: "active"` 的 Insight
- 分析時主動對照：本產業是否強化或挑戰現有 Insight？
- 第 9 節（反身性）與第 12 節（系統動作）強制引用相關 Insight ID

### C. 讀取相關 Bible（若存在）
```
data/coverage/ai-chips/{TICKER}.json
data/coverage/ai-infra-adjacent/{TICKER}.json
```
- 若分析產業與已覆蓋公司重疊，讀取對應 Bible
- 避免重複做別人已做過的基礎研究
- 有 Bible 可讀者，直接引用 Bible 中的財務數字與論點，不重新搜尋

## 分析框架

### 【第一節】分析框架選擇

根據產業特性，自動選擇分析框架並說明原因：

| 框架 | 適用情境 |
|---|---|
| 瓶頸框架 | 整條供應鏈有一個物理或認知瓶頸；找瓶頸控制者 |
| 週期框架 | 產業供需週期明顯；找週期位置與反轉信號 |
| 破壞框架 | 新技術正在替代舊技術；找替代速率與受害者 |
| 監管框架 | 監管決定市場結構；找監管前後的贏家輸家 |
| 網路效應框架 | 用戶規模決定競爭格局；找網路護城河強度 |

若多框架並存，主框架一個，輔助框架最多一個，說明主輔關係。

---

### 【第二節】市場邊界與規模

**市場邊界定義（必填）：**
- 包含什麼：{具體說明產品/服務範圍}
- 排除什麼：{避免誤入相鄰市場}
- TAM（Total Addressable Market）：{數字＋標注來源}

**規模量級感：**
```
全球 TAM：___（__年）[來源標注]
5年CAGR 預估：___% [來源標注]
台灣/亞太佔比：___% [來源標注（若適用）]
```

**規模判斷：**
- {大市場（>1000億美元）→ 說明為何未飽和}
- {中市場（100-1000億）→ 說明成長驅動力}
- {小市場（<100億）→ 說明利基壟斷邏輯}

### 【第三節】需求斜率分析

> 需求不是靜態數字，是帶方向的向量。

**需求驅動因子（3-5個，排序依重要性）：**

| 驅動因子 | 方向 | 強度 | 持久性 | 癌點（什麼讓它失效）|
|---|---|---|---|---|
| 因子A | ↑/↓ | 強/中/弱 | 結構性/週期性 | |
| 因子B | ↑/↓ | 強/中/弱 | 結構性/週期性 | |

**需求斜率判斷：**
- 現在在哪個階段：早期加速 / 成長中期 / 成熟高位 / 回落
- 最近一個季度需求變化方向的信號：{具體事件或數據}
- 未來 6-12 個月的需求斜率預估：{+/-__% + 理由}

**Jevons 悖論（適用時才填）：**
若此產業有效率改善導致需求反增的機制，標注 Jevons 悖論並說明傳導路徑。

---

### 【第四節】供給瓶頸分析

> 機會藏在哪裡最難被複製。

**供應鏈結構圖：**
```
上游（原材料/設備）→ 中游（製程/組裝）→ 下游（品牌/整合）→ 終端客戶
```
在各層標注：{集中度 + 換廠難度 + 主要玩家}

**瓶頸識別（最重要的一步）：**

| 層次 | 瓶頸存在？ | 瓶頸性質 | 控制者 | 可攻破時程 |
|---|---|---|---|---|
| 上游 | Y/N | 物理/認知/監管 | | |
| 中游 | Y/N | 物理/認知/監管 | | |
| 下游 | Y/N | 物理/認知/監管 | | |

**瓶頸評分（1-5分）：**
- 5分：物理性瓶頸，全球唯一，替代時程 > 5 年
- 4分：物理性瓶頸，少數寡占，替代時程 3-5 年
- 3分：認知型或監管型瓶頸，可被新技術或政策打開
- 2分：瓶頸存在但替代路徑清晰，1-3 年可突破
- 1分：無實質瓶頸，競爭開放

---

### 【第五節】技術替代風險

> 判斷「這個瓶頸的保存期限」。

**替代路徑掃描：**

| 替代技術 | 現況成熟度 | 替代速率預估 | 主要障礙 | 觀察指標 |
|---|---|---|---|---|
| 技術A | 商業化/研發/概念 | 快/中/慢 | 成本/物理/監管 | |
| 技術B | | | | |

**替代風險判斷：**
- **高風險（3年內可能替代）**：說明觸發條件
- **中風險（3-7年）**：說明為何市場未定價此風險
- **低風險（7年+）**：說明物理或結構性障礙

**CTO 參考（若技術前沿涉及 AI/半導體）：**
- CPO（Co-Packaged Optics）若適用，引用 CTO 最新評估
- 不做獨立技術預測，引用 `data/coverage/` Bible 或上次 CTO 輸出

### 【第十節】候選標的評分

**四分類系統：**

| 分類 | 定義 | 篩選標準 |
|---|---|---|
| 壟斷型 | 佔據不可替代位置，定價權極強 | 瓶頸分≥4 + 市佔>40% |
| 瓶頸型 | 控制供應鏈關鍵節點，非壟斷但難替代 | 瓶頸分≥3 + 轉換成本高 |
| 選擇型（期權）| 技術未成熟但方向正確，高風險高報酬 | 技術替代時程 2-5 年 + 資金充裕 |

## 輸出格式

```yaml
---
title: '【投資】{產業名稱}：{主論點摘要}'
description: '{60字內，包含為什麼現在＋最大機會＋最大風險}'
category: '投資'
subcategory: '美股'   # 或台股/其他投資
topic: '產業分析'
pubDate: 'YYYY-MM-DD'
---
```

**長度控制：**
- 前置摘要（三問答）：300字以內
- 第一節：100字
- 第二節：100字  
- 第三至八節：每節 150-250 字，**放入 `<details>` 折疊**
- 第九節：150字
- 第十節：評分表 + 100字說明
- 第十一節：Kill Switch 表 + 確認表
- 第十二節：裁示 3 點 + 系統動作
- **總字數目標：1500-2500 字**（不含 details 折疊內容）

**第三至八節折疊格式：**
```mdx
<details>
<summary>第三節：需求斜率</summary>

{內容}

</details>
```

## 嚴格限制

- **不做股價預測**，只分析結構與論點
- **不推薦買賣**，只產出「研究優先序」與「進場條件框架」
- **不重複 Bible 已有內容**，直接引用，不重新搜尋
- **不接受無數據支撐的結論**——每個主張必須接一個具體數字或事件
- 若搜尋不到某層數據，明確標注「資料不足，此節為方向性估計」
- MDX 禁止裸 `$數字`，改用中文或 `\$` 轉義
