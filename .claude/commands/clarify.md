# /clarify：需求拆解器

**輸入：$ARGUMENTS**

目標：把含糊的需求轉成具體、可執行、可驗收的目標清單。

---

## 設計原則

- **先推導，後提問**：不要一上來就問問題，先從輸入推導出所有能推導的，只有真正無法推導的才開口問
- **三層穿透**：任何需求都有三層——說出來的、想要的、不要的
- **目標必須可驗收**：每個目標能回答「完成了，我怎麼知道？」
- **假設顯性化**：把推導過程中的假設說出來，讓使用者確認或修正

---

## Step 1：讀入輸入

從 `$ARGUMENTS` 取得需求描述。

若 `$ARGUMENTS` 為空：輸出「請描述你的需求，越含糊越沒關係，我來拆解。」後停止。

---

## Step 2：三層分析（不問問題，先自己推導）

對輸入進行三層穿透分析，**內部執行，不輸出這個過程**：

**層一 — 字面層（說了什麼）**
- 把輸入重述一遍，確認理解沒有偏差
- 找出所有名詞（對象）、動詞（動作）、形容詞（品質條件）

**層二 — 意圖層（想解決什麼）**
- 問自己：「這個需求背後，真正想消除的痛點是什麼？」
- 問自己：「如果這個需求被完全滿足，最終狀態是什麼樣子？」
- 問自己：「這個需求是誰在什麼場景下產生的？」

**層三 — 邊界層（什麼不在範圍內）**
- 問自己：「這個需求明確或隱含地排除了什麼？」
- 問自己：「有哪些「看起來相關但其實不在需求裡」的東西？」

---

## Step 3：輸出拆解結果

用以下固定格式輸出，不省略任何一節：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔍 需求拆解｜[從輸入萃取的主題關鍵詞]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【一、理解確認】
你說的是：「[原始輸入原文]」
我的理解：[用一句完整的話重新描述，不改意思，只補完省略的主詞/受詞]

【二、真實意圖】
表面需求：[你說要什麼]
背後目標：[為什麼要這個，解決什麼問題]
成功狀態：[這件事做完，你希望什麼改變了？]

【三、具體目標清單】

每個目標格式：[序號]. **[動詞] + [對象]**，完成條件：[可驗收的標準]

[列出 3-7 個目標，從最核心到最外圍排列]

【四、範圍邊界】

✅ 包含：
- [明確在範圍內的事]

❌ 不包含：
- [隱含排除在外的事，或容易被誤解為在範圍內的事]

【五、推導假設】

我在拆解過程中做了以下假設，請確認是否正確：
- 假設 [A]，因為 [推導依據]
- 假設 [B]，因為 [推導依據]

若假設有誤，請告訴我哪裡錯了，我會重新拆解。

【六、待確認事項】（只列真正無法推導的）
```

若所有內容都能推導，第六節改為：

```
【六、待確認事項】
無。以上拆解若有偏差，直接告訴我修正哪條。
```

---

## Step 4：後續行動

輸出結果後，等待使用者回應：

| 使用者說 | 執行動作 |
|---|---|
| 「對」/ 「沒問題」/ 「就這樣」 | 輸出「目標已確認，可以開始執行。需要我直接產出執行計畫嗎？」|
| 修正某個目標 | 只改那條，其餘不動，重新輸出完整清單 |
| 「太多了」/ 「簡化」 | 只保留層二「背後目標」最直接相關的前三條目標，重新輸出 |
| 「還要加 [X]」 | 把 X 拆解後加入清單，標注「[新增]」，重新輸出 |
| 「幫我執行」 | 依目標清單，判斷是否有對應 agent 或 skill 可呼叫；若有，直接調度；若無，輸出逐步執行建議 |

---

## 範例

**輸入：** `/clarify 我想讓系統更智慧`

**輸出：**

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔍 需求拆解｜系統智慧化
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【一、理解確認】
你說的是：「讓系統更智慧」
我的理解：你希望 Xompass 系統在某些環節能主動判斷或減少你的決策負擔，而不是只被動等待你輸入指令。

【二、真實意圖】
表面需求：系統要「更智慧」
背後目標：減少重複性的手動觸發與決策，讓系統能在更多情境下自行判斷下一步
成功狀態：你在某些場景下不需要思考「要呼叫哪個 agent」，系統自己決定

【三、具體目標清單】

1. **識別輸入意圖**，完成條件：任何自然語言輸入，系統能自動分類到對應的 agent/skill，不需要使用者輸入 /指令
2. **主動提示下一步**，完成條件：agent 完成任務後，主動建議「下一個最有價值的動作」而非等待指令
3. **自動讀取上下文**，完成條件：每次執行前，系統自動讀入 regime/positions/picks，不需要手動提醒它「記得看持倉」
4. **異常自動預警**，完成條件：監控條件（Kill Switch、VCP 到期）觸發時，不等開會才發現

【四、範圍邊界】

✅ 包含：
- 路由與調度邏輯的改善
- 上下文自動注入機制
- 主動式提示設計

❌ 不包含：
- 改動現有 agent 的分析邏輯（不是「讓 CMO 更準」，那是另一件事）
- 引入新的外部 API 或工具
- 改動文章發布流程

【五、推導假設】
- 假設「系統」指 Xompass 的 Claude Code agent 架構，因為這是你目前的工具環境
- 假設「更智慧」指減少操作摩擦力，而非提升分析品質，因為你說的是「智慧」而非「準確」

【六、待確認事項】
無。以上拆解若有偏差，直接告訴我修正哪條。
```
