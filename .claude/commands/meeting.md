# /meeting：晨會

CEO 主導。目標不是報告資訊，是從資訊走到智慧。

```
資料 → 資訊（整理）→ 知識（關係）→ 智慧（推演）→ 裁定（行動）
```

Secretary 與 DNI 負責資料與資訊層。CEO 負責知識層與智慧層，主導全場。

---

## Step 0：上次會議複盤（Secretary 執行）

**在並行啟動之前，先由 Secretary 報告上次會議結論。**

Secretary 執行以下動作：

1. 列出 `data/meetings/` 目錄下所有 `.md` 檔案，取最新一份（按日期排序，取最後一個）
2. 讀取該檔案，找出：
   - **上次裁定**：上次會議的「今日裁定」段落（若有）
   - **待追蹤事項**：任何標記為「下一個確認點」、「若 X 發生」、或明確說「下次會議追蹤」的內容
3. 輸出格式：

```
## 上次會議複盤（{上次會議日期}）

**裁定回顧：**
- {上次裁定的論點狀態，一句話}
- {若有「下一個確認點」，說明是否已到期或已有結果}

**本次應追蹤：**
- {追蹤事項 1}（預計 {日期}，狀態：{已發生 / 未到期 / 結果：X}）
- {追蹤事項 2}（同上格式）

{若無待追蹤事項，填「上次無待追蹤事項」}
```

若 `data/meetings/` 目錄不存在或無任何檔案，跳過此步驟，直接進入 Step 1。

**同時檢查個股研究追蹤節點：**

讀取 `data/tracking/picks.json`，找出所有 `status: "pending"` 的推薦，計算今天日期與各 `reviews.weekN.due` 的差距：

- 差距 ≤ 1 天（含到期當日）：標記為「本次需追蹤」
- 已過期但未填寫：一併提報

若有到期追蹤，輸出：

```
**個股追蹤節點：**
- {TICKER}（推薦於 {recommended_date}，當時 {price_at_rec} 美元）
  → 第 N 週追蹤到期（{due日期}）：當前股價？論點是否仍成立？
```

若無到期項目，不輸出此段。

## Step -1：衝突驅動掃描（Secretary 執行，Step 0 完成後立即執行）

**目的：讓每日推演圍繞「維護世界觀」而非「複習功課」，解決資訊疲勞問題。**

Secretary 執行以下比對：

1. 讀取 `data/insights/insights.json`，取所有 `status: "active"` 的 Insight
2. 讀取最新 DNI 資料（`data/intel/YYYY-MM-DD.json`，取最新一份）
3. 對每條 Insight 的 `invalidation_signal` 與昨夜新聞比對，判斷是否有命中或偏差

**輸出格式（有衝突時）：**
```
## Insight 衝突警報

⚠️ [INS-ID] [Insight claim 一句話]
  前提假設：[invalidation_signal 中的具體前提]
  昨夜事件：[新聞標題 / 數據名稱]
  偏差說明：預期 [X 方向]，實際 [Y 數字或事件]
  建議處置：今日優先討論是否觸發失效 / 降低 confidence
```

**輸出格式（無衝突時）：**
```
昨夜無新事件觸發 Insight 衝突，推演基礎不變。Active Insights：[ID 列表]
```

**同時掃描 Insight 到期：**
- 距離 `expiry_check` 日期 ≤ 3 天的 Insight：提報「即將到期，建議今日決定：延期 / 失效 / 刪除」
- 已超過 `expiry_check` 但 status 仍為 active：標記為「逾期未審，需處置」

## Step 1：並行啟動（同一個 response turn）

同時呼叫四個 Agent，不等其中一個完成再呼叫另一個：

- `secretary`：報告近期行事曆（財報日、FOMC、重要經濟數據）+ 檢查 watchlist
- `dni`：抓取今日新聞（財經/科技/地緣政治/軍事四類），優先讀 `data/intel/` 快取
- `market-data`（TW post）+ `market-data`（US post）：依 `/close` Step 0 邏輯判斷最近收盤日，抓指數與法人數字
- `news-scout`（TW-market）+ `news-scout`（US-market）：同日期，各取 2 則

> 市場相關的四個 agent 依 `/close` Step 0-A 先判斷今天是否交易日、再決定要抓哪個日期。

---

## Step 2：呈現資訊層

按順序輸出：
1. 秘書簡報（行事曆 + watchlist 追蹤結果）
2. 情報長快報（四類新聞各 1-2 則，含投資相關性）

輸出保持精簡，資訊層到此為止。

---

## Step 3：市場現況｜CEO 合成

收到 market-data 與 news-scout 結果後，CEO 自行整合，輸出口語段落。

**格式與 `/close` 相同：**
- 不用 markdown 表格，純文字段落
- 台股先、美股後（若兩個都有）
- 每個市場：一句說數字（指數、漲跌幅），一句說主因（從新聞提煉）
- 若有特別值得注意的訊號（外資大量買賣、VIX 異常），加一句點出
- 最後一句連結兩市場方向，說明對本週開盤的含義

這段純描述，不做推演，讓 Step 4 的洞察提煉自己決定要不要深挖市場方向。

---

## Step 4：洞察提煉（資訊 → 知識）｜CEO 主導

**這步由 CEO 親自執行，不外包給其他 Agent。**

讀取今日所有資訊，找出 1-2 個「資訊之間的隱藏關係」——不是重複新聞說的話，而是幾則資訊放在一起後，才能看到的東西。

切入方式依當日情況選用：

| 情境 | 切入角 |
|---|---|
| 資訊互相矛盾 | 兩個事實同時為真，代表什麼？你必須選哪個？ |
| 資訊全部正向 | 這個好消息已被定價了嗎？沒被定價的在哪裡？ |
| 資訊全部負向 | 大家都在怕什麼？有沒有被錯殺的層次？ |
| 資訊不相關 | 今天沒有新資訊打到持倉——靜默本身代表什麼？ |
| 任何情況 | X 是真的，X 會導致什麼還沒人想到的事？ |

輸出格式：
```
## 洞察提煉

[資訊 A] × [資訊 B] → [兩者放在一起才能看到的關係，一句話說清楚]

這代表：[市場正在討論什麼] vs [市場還沒看到什麼]
```

## Step 5：推演鏈（知識 → 智慧）｜CEO 主導

**取最重要的那個洞察，往前推演 3-5 步。**

每一步標記確信度。越往後確信度越低，但也越可能是市場尚未定價的地方。

**推演前，先用 DSMM 框架校核傳導路徑（`src/content/notes/經濟/xompass-macro-framework.md`）：**

1. **入口市場**：這個衝擊從哪個市場開始？（財政 → 商品市場；貨幣 → 貨幣市場；地緣/能源 → 商品市場）
2. **速度排序**：金融市場最快反應，財政動態最慢——推演步驟順序必須符合此層級
3. **初始條件**：當前 Minsky 階段（對沖/投機/龐氏）決定傳導是線性還是非線性
4. **路徑鎖定檢查**：若 g-(r+ρ)→0 ＋ π^e 升 > Y 升 ＋ 殖利率倒掛/陡化並存，貨幣政策已失效，推演路徑鎖定

格式：
```
## 推演鏈

[觸發點]（入口市場：___）
  → [效應 1]（高確信，邏輯直接）
    → [效應 2]（高確信）
      → [效應 3]（中確信，開始有分叉）
        → [效應 4]（低確信，但若成真市場尚未定價）★

★ 標記處 = 我們領先共識的位置
```

推演規則：
- 每步必須說明邏輯，不能只跳結論
- 分叉點要說明哪個路徑更可能，以及什麼條件決定方向
- 最後一步必須連結到可觀測的現實（數據、事件、價格行為）

## Step 6：今日應裁定（提案，非定案）

**CEO 提出本次建議裁示，供董事長確認、修改或否決。**

### 輸出格式：先摘要、後附件

**主體（必填，4 點以內）：**

```
## 今日裁示摘要

**[最重要的等待點或行動]**：[一句話說清楚做什麼 / 不做什麼 / 等什麼]

**[本週最大發現]**：[市場還沒定價的那件事，一句話]

**[最大風險]**：[若 X 發生，Y 需立即複核]

**[觀察協議]**：[具體指標 + 閾值 + 對應行動]
```

**附件（用 `<details>` 可折疊，預設收合）：**

```
<details>
<summary>📊 市場現況（Step 3）</summary>

[Step 3 全文]

</details>

<details>
<summary>🔍 洞察提煉（Step 4）</summary>

[Step 4 全文]

</details>

<details>
<summary>🧠 推演鏈（Step 5）</summary>

[Step 5 全文]

</details>

<details>
<summary>📋 完整裁示細節</summary>

[Step 6 各項目的完整條件句版本]

</details>
```

輸出後，CEO 說：
> 「以上為本次建議裁示，請董事長確認，或提出修改、追加議題。」

不主動推進，等待董事長回應。

---

## Step 7：開放討論

董事長可以：
1. **確認裁示**：CEO 直接進入 Step 8 寫會議紀錄
2. **修改裁示**：CEO 更新對應項目，再次呈現修改後版本，等待確認
3. **追加議題**：CEO 依議題類型調度對應 Agent 深挖，結果接回討論

| 議題類型 | 調度對象 |
|---|---|
| 個股（NVDA/AMD/AVGO/QCOM） | `ai-infra-researcher` |
| 宏觀 / Regime | `cmo` |
| 供應鏈受益 | `/jade-report [事件]` |
| 產業分析 | `industry-analyst` |
| 財報細節 | `earnings-analyst` |
| 技術前沿 | `cto` |

深挖或討論完成後，CEO 更新裁示內容並再次確認，直到董事長說「可以」或「寫會議紀錄」。

---

## Step 8：會議紀錄

董事長確認後，CEO 整理本次會議內容，存入：

```
data/meetings/YYYY-MM-DD.md
```

紀錄結構：
```markdown
# 會議紀錄｜YYYY-MM-DD

## 資訊層摘要
（秘書 + DNI 重點，精簡）

## 市場現況
（Step 3 的口語段落）

## 洞察提煉
（Step 4）

## 推演鏈
（Step 5）

## 今日裁定
（最終確認版，非草稿版）

## 待追蹤（下次會議）
（下一個確認點 + 若 X 發生的條件）
```

存檔後告知董事長路徑，結束會議。

---

## 設計原則

- **CEO 主導分析，董事長裁示**：Step 1-5 是 CEO 的工作，Step 6 是提案，最終裁定由董事長確認
- **資訊是原料，不是產品**：Secretary 和 DNI 的輸出是素材，CEO 的推演才是會議的產出
- **每次會議必須有 ★ 標記**：至少找到一個市場尚未定價的推演步驟，這是領先共識的起點
- **裁定必須可以被驗證**：「下一個確認點」必須具體，讓下次會議可以回頭檢驗
- **會議紀錄在確認後才寫**：不在討論中途存檔，避免存入未定案內容
