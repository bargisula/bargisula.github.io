# /discuss：臨時專題討論

**用法：** `/discuss [主題或問題]`

針對特定問題展開深度討論。跳過新聞採集與行事曆，直接進入分析層。

---

## Step 1：背景定位

**CEO 執行，不外包。**

依主題類型，快速讀取相關背景資料：

| 主題類型 | 讀取來源 |
|---|---|
| 宏觀 / 利率 / Regime | `data/regime/current.json` |
| 個股（NVDA/AMD/AVGO/QCOM）| `data/coverage/ai-chips/{TICKER}.json` |
| 供應鏈標的 | `data/coverage/supply-chain/{TICKER}.md` |
| 持倉論點 | `data/positions/` 下相關檔案 |
| 無明確標的 | 跳過，直接進 Step 2 |

讀取後，用 1-2 句說明主題在當前 Regime 下的位置：

```
**定位：** 本議題屬於 [Regime 名稱] 的 [核心 / 邊緣 / 反向] 敘事。
當前 Regime 對此的預設立場是：[一句話]
```

---

## Step 2：洞察提煉

**CEO 執行，不外包。**

針對主題，從已知資訊中找出 1-2 個「隱藏關係」——不是重複已知說法，而是放在一起才能看到的東西。

切入方式：

| 情境 | 切入角 |
|---|---|
| 主題有明確數據 | 這個數字的含義比表面更深，在哪裡？ |
| 主題有兩個相反論點 | 兩個都對的話，代表什麼？必須選哪個？ |
| 主題是「大家都知道的事」 | 已被定價了嗎？沒被定價的在哪裡？ |
| 主題是尾端風險 | 大家都在怕什麼？有沒有被錯殺的層次？ |

輸出格式：
```
## 洞察提煉

[已知事實 A] × [已知事實 B] → [兩者放在一起才能看到的關係]

這代表：[市場正在討論什麼] vs [市場還沒看到什麼]
```

---

## Step 3：推演鏈

**CEO 執行，取最重要洞察往前推演 3-5 步。**

每步標記確信度，最後一步必須連結到可觀測的現實。

格式：
```
## 推演鏈

[觸發點]
  → [效應 1]（高確信，邏輯直接）
    → [效應 2]（高確信）
      → [效應 3]（中確信，開始有分叉）
        → [效應 4]（低確信，但若成真市場尚未定價）★

★ 標記處 = 我們領先共識的位置
```

規則：
- 每步必須說明邏輯，不能只跳結論
- 分叉點說明哪個路徑更可能，以及什麼條件決定方向
- 最後一步連結到可觀測的現實（數據、事件、價格行為）

---

## Step 4：裁定

格式：
```
## 裁定

給定今日推演：
- [Regime / 持倉 / 關注標的] 狀態：[強化 / 不變 / 弱化 / 需行動]
- 下一個確認點：[具體事件或數據] 預計 [日期]
- 若 [X 發生]，重新評估 [Y]
```

---

## Step 5：深挖（視需要）

裁定後，CEO 主動提出最值得繼續深挖的方向，調度對應 Agent：

| 問題類型 | 調度對象 |
|---|---|
| 個股（NVDA/AMD/AVGO/QCOM） | `ai-infra-researcher` |
| 宏觀 / Regime | `chief-economist` |
| 供應鏈受益 | `/jade-report [事件]` |
| 產業分析 | `industry-analyst` |
| 財報細節 | `earnings-analyst` |
| 技術前沿 | `cto` |

深挖完成後，CEO 將新資訊接回推演鏈，判斷是否修正裁定。

---

## 結束：存會議紀錄

討論結束時，存檔至：

```
data/meetings/YYYY-MM-DD-{主題關鍵詞}.md
```

若同日已有晨會紀錄（`YYYY-MM-DD.md`），不覆蓋，另存為獨立檔案。

---

## 設計原則

- **輕量啟動**：不跑 Secretary / DNI，省去 60-90 秒，直接進分析
- **主題驅動**：從董事長的問題出發，不從新聞堆砌
- **與晨會銜接**：若討論出新的「待追蹤事項」，在裁定中明確標出，下次晨會 Step 0 會追蹤
