# /news-trigger：新聞論點觸發器

**用法：** 由 CEO 晨會 Step 1 完成後自動呼叫，不需手動觸發

**目的：** DNI 收集的新聞 → 比對 trigger-map → 判斷是否實質影響現有論點 → 輸出行動建議

---

## 設計原則

兩層過濾，寧可漏報，不要誤報：
- **第一層（關鍵詞）**：便宜、快速，排除明顯無關新聞
- **第二層（語意判斷）**：只對通過第一層的新聞做，判斷是否「實質影響論點前提」

**觸發門檻定義：** 不是「有提到這個板塊」，而是「這則新聞如果成真，會改變某個支撐條件（C）的狀態或觸發某個 Kill Switch（K）」

---

## 執行流程

### Step 0：讀取資料來源

```bash
# 1. 今日新聞
cat data/intel/$(date +%Y-%m-%d).json   # 若無則讀最近一個
ls -t data/intel/*.json | head -1        # 備用

# 2. 觸發詞地圖
cat data/positions/trigger-map.json

# 3. 現有 signals（確認哪些板塊在追蹤中）
ls -t data/signals/*.json | head -1
```

---

### Step 1：第一層篩選（關鍵詞比對）

對每則新聞（標題 + 摘要）：

```
掃描 trigger-map 所有板塊的：
  - conditions[*].watch_keywords
  - conditions[*].kill_keywords
  - tickers 清單

任一命中 → 記錄（新聞ID, 板塊, 命中詞, 命中類型: watch/kill/ticker）
全部未命中 → 丟棄
```

若第一層零命中 → 輸出「今日無新聞觸發」，結束。

---

### Step 2：第二層語意判斷（對每筆命中）

對每筆命中的（新聞, 板塊, 條件），判斷：

**判斷問題：「假設這則新聞描述的事情屬實，它是否會改變 [條件描述] 的成立狀態？」**

```
判斷結果三選一：
  ✅ 實質影響（正向）：支撐條件加強 → 記錄，建議「確認後更新 position 檔」
  ❌ 實質影響（負向）：支撐條件弱化或 Kill Switch 預警 → 記錄，建議「立即通知」
  🟡 背景資訊：提到相關主題但不影響條件判斷 → 丟棄，不輸出
```

**負向判斷加速規則（不需第二層直接觸發）：**
- 新聞命中任一 `kill_keywords` → 直接標記為「❌ Kill Switch 預警」，跳過第二層
- 理由：Kill Switch 是事先定義好的失效條件，命中即預警，不需再判斷

---

### Step 3：輸出結果

```
📰 新聞觸發結果｜YYYY-MM-DD

⚠️ Kill Switch 預警（優先處理）
━━━━━━━━━━━━━━━━━━━━━━━━
[若有]
  板塊：[板塊名稱]
  條件：[K幾：描述]
  新聞：[標題] — [一句白話說為什麼觸發]
  建議：立即呼叫 earnings-analyst / position-check，確認是否已觸發

━━━━━━━━━━━━━━━━━━━━━━━━
✅ 論點加強信號
━━━━━━━━━━━━━━━━━━━━━━━━
[若有]
  板塊：[板塊名稱]
  條件：[C幾：描述]
  新聞：[標題] — [說明如何加強論點]

━━━━━━━━━━━━━━━━━━━━━━━━

```

---

### Step 4：行動路由

依輸出結果自動路由：

**Kill Switch 預警：**
```
→ 立即在晨會第三節置頂顯示（用 ⚠️ 紅色標示）
→ 建議董事長確認後呼叫 position-check 或 earnings-analyst
→ 不自動修改 position 檔（Kill Switch 觸發是重大決策，需人工確認）
```

**論點加強信號：**
```
→ 在晨會第三節對應板塊下方加一行引用
→ 若有 position 檔：建議更新對應條件（不自動執行，等董事長確認）
→ 若無 position 檔：在 suggested_action 加注「新聞支撐，建議建立 position 檔」
```

**今日無觸發：**
```
→ 不在晨會報告中顯示任何內容（不佔版面）
```

---

## 執行頻率

- **晨會時**：CEO Step 1 完成後自動執行一次
- **董事長說「掃新聞」「比對論點」**：手動觸發

---

## 觸發詞維護規則

`data/positions/trigger-map.json` 的更新時機：
- 建立新 position 檔時 → 同步新增對應板塊觸發詞
- Kill Switch 更新時 → 同步更新 kill_keywords
- 出現誤報（非相關新聞頻繁觸發）→ 移除或縮窄關鍵詞
- 出現漏報（明顯相關新聞未觸發）→ 新增關鍵詞
