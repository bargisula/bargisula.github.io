# 產業技術分析框架 SKILL

## 核心方法論：瓶頸→溢出

分析任何技術關鍵詞時，先找「誰是瓶頸」，再推「瓶頸卡住時，需求往哪裡溢出」。

```
瓶頸（現有技術物理/成本極限）
  ↓
需求溢出（新技術/替代路線）
  ↓
直接受益（第一層供應鏈）
  ↓
間接受益（第二、三層供應鏈）
  ↓
輸家（被替代者）
```

**判斷「現在在哪裡」：**
- 敘事期：技術未量產、無營收數字、股價反映預期
- 數字期：試產良率出爐、訂單確認、資本支出計畫明確

---

## 六模組結構

### 模組 1：技術定位
- 一句話說明「這是什麼」
- 為什麼「現在」重要（觸發點：競爭對手動作、物理極限、成本臨界）
- 與現有技術的關鍵差異表格（Callout type="data"）

### 模組 2：供應鏈卡片
- 三層結構：核心製造 / 設備材料 / 上游原材料
- 每個環節：台灣標的股票代號、角色說明
- 若台廠目前空缺某環節，必須標注（潛在機會或風險）
- 使用 Callout type="data" 做表格

### 模組 3：瓶頸→溢出分析（核心）
- 先說清楚現有技術的瓶頸是什麼（物理限制、良率問題、成本障礙）
- 量化瓶頸：給出具體數字（面積利用率、良率、成本差距）
- 畫出溢出方向：條列誰受益、誰受壓
- 使用 Callout type="warning" 框出瓶頸描述
- 結尾一條量化換算（例：面積利用率差 X% = 有效產出差 Y%）

### 模組 4：現在在哪裡
- 明確標注：敘事期 / 數字期
- 給出時間軸：試產 → 量產 → 主流
- 投資含義：敘事期適合小部位長持，數字期才是加碼點
- 使用 Callout type="insight"

### 模組 5：關注清單
- 3–5 個具體可觀察的檢查點
- 每個檢查點：目標是什麼、觀察方式（法說、技術論文、月營收）
- 使用 Callout type="warning"

### 模組 6：誰是輸家
- 被替代的現有技術供應商
- 無法升級的傳統環節
- 供應鏈外流的環節（台廠空缺）
- 使用 Callout type="warning" 表格

## 寫作規則

**Callout type 使用規範（只有這五種）：**
| type | 用途 |
|---|---|
| data | 數據表格、供應鏈結構、時間軸 |
| insight | 正面機會、突破訊號、受益邏輯 |
| warning | 風險、瓶頸描述、輸家、值得注意 |
| quote | 一句話結論、核心論點收尾 |
| link | 外部參考連結 |

**禁用：** `type="info"` — 不存在此類型，會造成 build error

> 📝 此寫作規則與 us-tech-analysis 保持一致。若修改 Callout 規範或 MDX 規則，須同步更新兩個 skill。

**MDX 第一行（必填）：**
```
import Callout from '../../../../components/Callout.astro';
```
（路徑依文章所在目錄深度調整，台股目錄固定使用此路徑）

**frontmatter 必填欄位：**
```yaml
title: '[技術名稱]：[15字內核心論點，含方向性判斷]'
description: '[60字內，含技術定位、受益邏輯、一個關鍵數字]'
category: '投資'
subcategory: '台股'
topic: '產業分析'
pubDate: 'YYYY-MM-DD'
```

**深度與密度原則：**
- 每個數字都要有來源語境（不要孤立數字）
- 瓶頸→溢出必須給出量化換算，讀者要能自己算帳
- 輸家必須點名，不能只說「傳統業者受壓」
- 時間軸必須具體（年份），不能說「未來幾年」
