# AI 基礎設施新聞解讀 SKILL

## 核心框架：六層瓶頸地圖

每則 AI 新聞都可以對應到供應鏈的某一層（或多層）。分析前先定位，再往下展開。

```
① 需求端（誰在花錢）   → Hyperscaler 資本支出、主權 AI
② 算力層（晶片）       → GPU / ASIC / 製程
③ 記憶體層             → HBM / NAND / HDD / DRAM
④ 封裝層               → CoWoS / CoPoS / CPO / SoIC
⑤ 網路層               → IB / 乙太 / 光模組 / CPO
⑥ 基建層               → 伺服器 ODM / 電力 / 散熱
```

詳細知識庫：
- `references/six-layers.md`：各層定義、現況、關鍵指標
- `references/company-map.md`：各公司在供應鏈的定位與當前狀態
- `references/timeline.md`：技術發展時程表
- `references/ai-regulation.md`：AI 監管框架、模型安全爭議、公司監管立場（EU AI Act、Mythos、GPAI）

## 執行流程

### 步驟 1：讀取知識庫

分析前先讀取：
- `references/six-layers.md`
- `references/company-map.md`
- `references/timeline.md`

### 步驟 2：解析新聞內容

從使用者提供的新聞中提取：
- **事件主體**：哪家公司 / 哪項技術 / 哪個市場
- **事件性質**：財報 / 技術突破 / 供需變化 / 政策 / 地緣 / 併購
- **數字**：金額、成長率、時程、市占等

### 步驟 3：定位到六層框架

判斷這則新聞主要影響哪一層（可能跨層）：

| 如果新聞關於… | 對應到… |
|---|---|
| NVIDIA、AMD、Google TPU、ASIC | ② 算力層 |
| HBM、NAND、SSD、HDD、DRAM | ③ 記憶體層 |
| CoWoS、CoPoS、CPO、封裝 | ④ 封裝層 |
| 光模組、InfiniBand、乙太網路、交換器 | ⑤ 網路層 |
| 台積電製程（N2/N3/A14）| ② + ④ 跨層 |
| AWS / Azure / Google Cloud 資本支出 | ① 需求端 |
| 廣達、鴻海、緯穎、Super Micro | ⑥ 基建層 |
| 電力、散熱、液冷 | ⑥ 基建層 |
| 出口管制、地緣政治 | 跨層（判斷受影響最大的層） |

### 步驟 4：展開影響鏈（瀑布分析）

```
事件
  ↓
第一層直接衝擊（最直接受益 / 受壓的公司）
  ↓
第二層溢出（供應鏈上下游的連動）
  ↓
輸家（誰被替代 / 誰的市場被壓縮）
  ↓
反向問：「這件事如果沒發生 / 反轉，誰最受傷？」
```

### 步驟 5：產出結構化分析

輸出格式如下（對話中回覆，不寫檔）：

```
📍 影響層：[層次名稱]

【事件摘要】
[一句話說清楚發生了什麼]

【第一層衝擊】
✅ 受益：[公司]（Ticker）— [原因，一句話]
⚠️ 受壓：[公司]（Ticker）— [原因，一句話]

【第二層溢出】
[上下游連動，1–3 點]

【輸家】
[被替代或市場被壓縮的對象]

【投資訊號】
強度：強 / 中 / 弱
時程：短期（1–4週）/ 中期（1–3季）/ 長期（1–3年）
方向：偏多 / 偏空 / 中性

【是否超前 / 落後時程？】
對照 references/timeline.md，判斷這個消息相對市場預期是：
  - 超前預期 → 可能帶來估值重估
  - 符合預期 → 已 price-in，影響有限
  - 落後預期 → 負面訊號，可能觸發賣壓

【需要追蹤的指標】
[1–2 個後續觀察點]
```

## 步驟 6（新聞擴充搜尋）

使用者給一則新聞後，**主動搜尋相關新聞**以擴充分析深度：

### 搜尋範圍（每次分析都執行）

**1. 主體公司近況**
搜尋主角公司最近 2–4 週的重要動態（財報、法說、合作、產品）

**2. 上游一層**
主角公司的供應商 / 技術提供者的最新消息
例：博通 → 搜尋台積電 CoWoS 相關、NVIDIA ASIC 合作動態

**3. 下游一層**
主角公司的主要客戶 / 應用場景的最新消息
例：博通 → 搜尋 Google TPU 部署、Meta ASIC 進度

搜尋結果納入分析，並在輸出時標注「擴充來源」，讓分析不只依賴單一新聞。

## 步驟 7：詢問是否記錄與更新

分析完成後**必須詢問**，不得自動執行任何寫入動作：

```
💬 分析完成。請選擇後續動作：

  「記」→ 調用 flash skill，記錄為市場快訊（推上部落格）
  「更新知識庫」→ 將本次新發現的公司/事件/時程更新到 references/ 檔案
  「兩個都做」→ 同時記錄快訊並更新知識庫
  「不用」→ 結束，不寫入任何檔案
```

**重要規則：**
- 無論分析結果多確定，**未收到明確指令前不寫入任何檔案**
- 包括 flash 快訊、references/ 知識庫、skill.md 本身
- 使用者可能用假資料測試，寫入需要明確確認
- 知識庫更新是**動態成長**的機制：每次確認後才將新資訊沉澱進 references/

## 特殊情境處理

### 技術突破類新聞
對照 `references/timeline.md`，判斷比原定時程超前還是落後。
超前 = 正面催化劑（可能觸發估值重估）
落後 = 負面訊號（市場可能已 price-in 更樂觀預期）

### 供需變化類新聞（缺貨 / 過剩）
對照 `references/company-map.md`，找出定價能力最強的廠商，判斷漲價空間。

### 地緣政治 / 出口管制
先判斷哪條供應鏈受影響最大，再找替代路徑（中國替代品、繞道方案）。

### 財報類新聞
對照預期：超預期 → 判斷是否可持續；不如預期 → 是一次性因素還是結構性問題。
