## 一句話定論

微軟這次 Build 不是發布新產品，是在宣告一個新的作業系統層：**讓 Windows、Azure、Bing 變成服務 AI 代理的底層基礎設施**，而不是服務人類的應用程式平台。

這和 PC 時代微軟做的事本質上一樣——不一定做最好的應用，但掌控生態系統的分發與執行層。

---

## 二、為什麼這個時間點重要

AI 應用的滲透目前卡在一個結構性瓶頸：**大多數用戶停留在「問答模式」**。

提問 → 得到答案 → 自行決策與執行，AI 本質上只是功能更強的搜尋框。這個模式的天花板很低，無法釋放 AI 真正的生產力溢價。

AI 代理（Agent）打破這個瓶頸的方式是**把執行層交出去**：用戶給定目標，代理自行拆解任務、調用工具、執行操作、交付結果，全程不需要人工逐步介入。

<Callout type="insight">
**自動駕駛 vs 語音導航的比喻非常精準。**
語音導航告訴你往哪轉，但你還要踩油門、停車、找停車位；自動駕駛則是你說「帶我去機場」，然後下車。

AI 代理與 AI 助理的差距，就是這兩種模式的差距。微軟要做的，是讓整個 Windows 生態成為「自動駕駛的道路系統」。
</Callout>

問題是：AI 代理要「執行」，就需要一個可信任、安全隔離、跨應用調用的執行環境。這個環境現在不存在。Build 2025 要建的，就是這個。

## 三、技術解構：四個積木，一個架構

### Web IQ — 給代理看的 Bing

傳統搜尋引擎是給人類設計的：輸入關鍵字、看清單、點連結。Web IQ 重新定義了這個介面——**讓 AI 代理直接查詢即時資訊並調用網站服務**，而不需要人類中介。

三個實際能力：
1. **即時資訊接入**：代理可以取得今天的新聞、當前價格、最新文件，解決大型語言模型的資訊截止日問題
2. **服務調用**：代理可以直接完成交易（訂票、預約、購買），而不只是顯示連結
3. **多代理情境共享**：不同功能的代理（搜尋、推理、執行、驗證）可以共享同一份即時網路情境

這和 MCP（Model Context Protocol）高度整合——未來網站要服務的對象不只是瀏覽器，還有代理。

### Solara — 代理原生的裝置平台

Solara 的邏輯是：**如果 AI 代理是新的操作介面，那麼 Windows 的使用者介面就必須重新設計**。

用戶不再開啟應用程式；用戶說出目標，代理完成任務，應用程式只是背景被調用的工具。

這是一個激進的重構，但配合 1.4 億台 Windows 活躍裝置，執行力是真實的。

### MXC — 代理的安全沙盒

MXC（Microsoft eXecution Container）是 AI 代理的作業系統級隔離容器。

代理執行任務時，需要同時接觸日曆、郵件、瀏覽器、財務數據——但這帶來嚴重的安全與隱私風險。MXC 的作用是在系統層提供可信執行環境，讓企業能夠放心部署代理。

OpenAI 與 NVIDIA 已加入生態建設，這是一個重要訊號：這不是微軟的單邊宣示，而是正在形成的產業標準。

### WAF + Helios — 開發者平台的補完

Windows Agent Framework（WAF）讓開發者直接在 Windows 上封裝、部署和管理代理，調用系統資源。即將推出的 Windows 11「Helios」更新將內建原生代理執行環境。

**這是微軟最關鍵的一步**：讓第三方開發者在 Windows 平台上建構代理，重現 Win32 API 時代建立的生態護城河。

## 四、五張護城河

<Callout type="data">
| 資產 | 規模 | 護城河強度 |
|------|------|-----------|
| Azure 雲端 | 2025 會計年度營收逾 750 億美元，年增 34% | ⬛⬛⬛⬛⬛ 極強 |
| Copilot MAU | 月活超過 1 億，GitHub Copilot 逾 2,000 萬用戶 | ⬛⬛⬛⬛⬜ 強 |
| Windows 裝置 | 全球逾 14 億台活躍裝置 | ⬛⬛⬛⬛⬛ 極強（分發） |
| OpenAI 綁定 | 不需自建模型層護城河 | ⬛⬛⬛⬜⬜ 中（風險：依賴單一夥伴） |
| 企業資料主權 | M365 涵蓋全球最多企業辦公數據 | ⬛⬛⬛⬛⬛ 極強（難複製） |
</Callout>

納德拉在內部會議說的那句話值得反覆思考：「未來 AI 市場的價值將向**協議層與資料層**集中。」

這句話的含意是：微軟放棄與 Anthropic、Google DeepMind 在模型層競賽，轉而確保代理要執行任何任務，都必須經過微軟的協議層（MCP）和資料層（M365、Azure）。

## 五、競爭格局：各家路徑不同，護城河各異

<Callout type="data">
| 競爭者 | 核心優勢 | 與微軟的差異 |
|--------|---------|-------------|
| **Google (GOOGL)** | 搜尋入口、消費者數據、Gemini 全堆疊整合 | 消費者端強，企業端弱；搜尋收入受代理衝擊最直接 |
| **Apple (AAPL)** | 裝置端隱私運算、iOS 生態深度整合 | 封閉生態難開放；企業市場幾乎缺席 |
| **Anthropic (Claude)** | 模型安全性、企業合規 | 無作業系統、無搜尋、無企業辦公套件 |
| **微軟 (MSFT)** | 唯一同時擁有 OS + 辦公套件 + 雲端 + 搜尋 + 開發者平台 + 頂尖模型夥伴 | 生態整合深度無競爭對手 |
</Callout>

**Google 是最直接的威脅，但也是最直接的受害者**：搜尋廣告模式在代理時代面臨根本性衝擊（代理不「看」搜尋廣告）。Google 必須在破壞自己的核心業務和輸給微軟之間選擇一個。

微軟沒有這個兩難——Bing 的廣告收入從來就不是微軟的核心，它只是一個分發入口。

## 六、投資含義

**短期（0-12 個月）**：Build 2025 是敘事催化劑，不是財務事件。這些技術需要時間從發布走到商業化，直接財務衝擊需等到 FY2027 才會顯著。

**中期（12-36 個月）**：關鍵指標是 Copilot 的 ARPU（每用戶平均收入）趨勢，以及 Azure 在代理工作負載的份額。Azure 目前 34% 的年增率若能在代理需求的推動下加速，估值重定價空間顯著。

**生態系受益者**：
- **NVDA**：代理執行需要更多推論算力，MXC 生態建設 NVDA 參與其中
- **MSFT**：直接受益，但估值已反映大量預期
- **GitHub Copilot 生態**：2,000 萬開發者是 WAF 的天然種子用戶

<Callout type="warning">
**貨幣化模式尚未清晰，是最大的不確定性。**

AI 代理的定價模式是以「任務」計費、以「時間」計費、還是沿用現有的 per-seat 模式？這個問題尚未解決。若採用 per-seat，收入天花板受限；若採用使用量計費，毛利率結構將大幅改變。

在商業模式明確之前，Build 2025 的敘事很強，但財務模型很難寫。
</Callout>

## 七、論點失效條件（Kill Switch）

這個論點成立的前提，以及會讓它失效的條件：

| 前提 | 驗證方式 | 失效訊號 |
|------|---------|---------|
| OpenAI 關係穩定 | 微軟/OpenAI 合約續期 | OpenAI 大規模轉向 Apple 或 Google |
| 企業採用速度正常 | Copilot 企業 ARPU 季增率 | 連續兩季 ARPU 環比負成長 |
| MXC 成為產業標準 | 第三方代理框架採用 WAF | 主流開發者轉向 Google Agent Space 或 AWS Bedrock |
| Azure 維持份額 | 季報 Azure 年增率 | Azure 年增率跌破 25%，份額轉移給 AWS |

<Callout type="insight">
**最需要追蹤的單一指標：GitHub Copilot 活躍用戶從 2,000 萬成長到 5,000 萬的時間軸。**

開發者是代理生態最早的採用者，也是最能反映 WAF 真實吸引力的指標。Copilot 的用戶增長曲線，是微軟代理平台論點最早出現的驗證訊號。
</Callout>

## 八、結語：微軟在做它最擅長的事

微軟的歷史模式從來不是「做最好的產品」——它做的是「讓每個最好的產品都必須跑在微軟的平台上」。

PC 時代是 Windows + Office；雲端時代是 Azure + GitHub；現在是 Windows + Azure + MCP + WAF。

代理時代的核心資源是：**可信任的執行環境 + 企業資料主權 + 開發者生態**。這三樣微軟都有，且都具備顯著的先發規模優勢。

這不保證微軟贏，但它確實是這場賭局中最難被複製的一手牌。
