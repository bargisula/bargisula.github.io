Sakana AI 在 2025 年 5 月發表了一篇技術立場鮮明的論文，名為 **Continuous Thought Machines（CTM）**，arXiv 編號 2505.05522。作者包括 Llion Jones——他是 2017 年原版 Transformer 論文「Attention is All You Need」的八位作者之一。

這不是一般的模型改良論文。CTM 的主張是：**Transformer 的記憶體設計從根本上走錯了方向**。

---

## 先搞清楚命名

這篇論文的正式名稱是「Continuous Thought Machines」，不是「Continuous Transformer Memory」。Sakana 在 2024 年 10 月還有另一篇前作 NAMM（An Evolved Universal Transformer Memory），是用演化演算法管理 KV Cache——兩者是不同的研究，但屬於同一條路線：讓模型「學會如何管理自己的記憶」，而不是由人工設計記憶機制。

---

## Transformer 的根本限制是什麼？

要理解 CTM，先要理解它在解決什麼問題。

標準 Transformer 有一個非直覺的限制：**計算深度是固定的，與問題難度無關。** 不管你問「2+2 等於幾」還是「請推導黎曼猜想」，模型都跑同樣層數的計算。它是一個精密的模式比對機器，在前向傳遞中沒有自我修正的迴路——卡住了也無法「多想一下」。

現有的解決嘗試各有根本限制：

| 機制 | 核心邏輯 | 根本限制 |
|---|---|---|
| KV Cache | 存住過去的 attention key/value | 推論加速，不是推理深度 |
| RAG | 外掛知識庫查詢後拼進來 | 記憶靜態、外掛，模型不學如何記憶 |
| Mamba / SSM | 遞迴狀態壓縮序列 | 固定維度壓縮，表達力有限 |
| Chain-of-Thought | 用 token 輸出草稿來推理 | 推理在明文空間，成本隨深度平方增長 |

CTM 的方向不一樣：把推理從「token 輸出空間」搬到「神經元時序空間」。

---

## CTM 的核心設計

### 每個神經元都有自己的記憶

傳統神經元是一個無狀態的靜態函數：接收輸入、輸出一個數、完全不記得上一步做了什麼。同樣的輸入在第 1 步和第 1000 步，輸出完全相同。

CTM 給每個神經元配備一個「私有小模型（Neuron-Level Model，NLM）」，這個小模型處理的是「這個神經元過去 M 個時間步的激活歷史」，用這段歷史計算下一步的輸出。

```
傳統神經元：
  輸入 × 權重 → 激活函數 → 輸出（無狀態）

CTM 神經元：
  輸入 × 權重 → NLM（讀自身歷史 M 步）→ 輸出（有狀態）
```

**記憶不再是集中式結構（KV Cache、State Vector），而是分散在每一個神經元裡，以時序動態的形式存在。**

### 「連續」的兩層含義

**時間連續：** CTM 引入獨立的「內部時間軸（internal ticks）」，與輸入序列解耦。模型在這個時間軸上持續迭代，直到「準備好了」才輸出。可變的 tick 數讓模型能根據問題難度自適應深度。

**空間連續：** 潛在表示不是某一層的激活值快照，而是神經元之間激活時序的**同步性（synchronization）**——誰和誰同時變動、誰比誰早。這個設計直接來自計算神經科學的突觸可塑性（STDP）理論。

---

## Tick 不等於 Token：最關鍵的差異

CTM 最值得被質疑的地方，也是最容易被誤解的地方：**tick 消耗算力，但算力的 scaling 形狀不一樣。**

<Callout type="insight">
Tick 不是免費的，但 tick 的成本結構與 token 根本不同——後者越算越貴，前者固定成本。
</Callout>

CoT 的問題不只是「算了幾步」，而是每多一步，後面每步都更貴：

```
CoT 成本：
  Step 1：Attention 計算量 ∝ n²
  Step 2：Attention 計算量 ∝ (n+1)²  ← 前一步 token 進了 context
  Step 3：Attention 計算量 ∝ (n+2)²
  → 推理越深，每步越貴，成本是平方增長
  → KV Cache 持續膨脹

CTM 成本：
  Tick 1：計算量 = C（固定，神經元數量決定）
  Tick 2：計算量 = C
  Tick 3：計算量 = C
  → 不管推理多深，每個 tick 成本一樣
  → 不產生 token，不進 context，KV Cache 不增長
```

**CTM 的核心主張不是「推理不花錢」，而是「推理成本不會隨深度加速增長」。**

這也與 OpenAI o1 / o3 的「隱藏思考 token」本質不同：

| | o1 / o3 隱藏 token | CTM tick |
|---|---|---|
| 存在形式 | 還是 token，只是不顯示 | 神經元激活值，非 token |
| 會進 context 嗎 | 會，成本仍是平方增長 | 不會，成本固定 |
| 本質 | 帳單不給你看 | 帳單結構不一樣 |

## 硬體影響：ASIC 與 GPU 的命運分歧

這是 CTM 對投資最直接的含意。

### ASIC 需要幾乎全面重新設計

Google TPU、Broadcom 客製 ASIC 的設計核心是 Systolic Array（脈動陣列）：把 Transformer 的靜態計算圖燒進電路，用特化換效率。CTM 的需求與這個哲學正面衝突：

| CTM 需求 | 與現行 ASIC 的衝突 |
|---|---|
| 每個神經元有獨立 NLM | Systolic Array 假設「所有神經元跑同樣計算」|
| Tick 數動態決定 | 靜態計算圖無法燒進電路 |
| N 個獨立 history buffer | SRAM bank 設計對不上不規則存取模式 |
| 神經元時序同步性是表示 | 現行 ASIC 完全沒有時序計測邏輯 |

不是修改電路，是設計哲學重來。

### GPU + CUDA：不用重新設計，但效率差

GPU 的本質是通用並行計算，CUDA 讓它可以跑任何程式。CTM 今天就可以用 PyTorch 實作在 GPU 上執行：每個 NLM 仍是小型矩陣乘法，tick 迴圈用動態計算圖處理。

但效率差的結構性原因：N 個獨立 buffer 的分散讀寫導致快取命中率低，HBM 頻寬浪費；GPU 喜歡大批次，CTM 的小粒度計算不對胃口。這不是調參數可以解決的，是存取模式的根本衝突。

<Callout type="data">
最符合 CTM 需求的硬體是神經形態晶片（Intel Loihi 2、IBM NorthPole）——非同步、有狀態的神經元引擎，設計哲學天然對齊。但這個生態系目前仍在早期。
</Callout>

## 投資含意：一個結構性的反轉假設

目前市場的趨勢方向是：**GPU（通用）→ ASIC（特化）**，理由是 Transformer 計算圖固定，特化程度越高效率越好。Broadcom 的 ASIC 業務高速增長就建立在這個假設上。

CTM 若成立，這個方向可能逆轉：

```
動態計算圖 + 不規則記憶體存取
→ 固定電路的優勢消失
→ 彈性反而比特化更有價值
→ GPU 的通用性重新勝出
```

這不是說 CTM 會在短期衝擊 Broadcom 的生意。而是說：**ASIC 的護城河建立在「Transformer 計算圖是固定的」這個假設上，這個假設正在被嚴肅地挑戰。**

## 現在在哪個階段？

<Callout type="warning">
CTM 目前只在 2D 迷宮、分類、排序等玩具任務上驗證。語言模型實驗是空白。作者自己說「目標是分享創新，不是追最先進基準」。
</Callout>

| 里程碑 | 狀態 |
|---|---|
| 論文發表 | ✅ 2025 年 5 月 |
| 玩具任務驗證 | ✅ 迷宮、分類、排序 |
| 語言模型實驗 | ❌ 空白 |
| 大規模預訓練 | ❌ 未嘗試 |
| 計算效率優化 | ❌ 比同規模 Transformer 慢 |
| 產品化 | ❌ 不可見 |

**唯一值得追蹤的時間點：CTM 第一篇語言建模任務的實驗論文。** 那才是 Phase 1 → Phase 2 的真正信號，距今估計至少 18 個月。

## 為什麼是 Sakana？

Sakana AI 由 David Ha（前 Google Brain 研究主任）和 Llion Jones（Transformer 原作者之一）共同創辦，研究風格有兩個特徵直接指向 CTM：

**反規模化：** 不相信堆 GPU 是正確路徑。代表作包括 EvoTransformers（演化搜尋架構）和 AI Scientist（自動化科研）。CTM 是同一邏輯：用神經元動態取代暴力堆層數。

**神經科學橋接：** CTM 裡的 STDP 啟發和「神經同步作為表示」是嚴肅的神經科學語言，不是行銷標籤。

NAMM（2024）和 CTM（2025）合在一起是一個完整論述：現有 Transformer 的記憶體設計是根本性的錯誤方向，需要從神經元動態重建。

## 底線

CTM 是技術立場鮮明、實驗仍初步的研究。市場定價接近零——Sakana 未上市，NVDA / AVGO 等半導體公司的估值完全建立在 Transformer 基礎設施擴張上，CTM 的架構挑戰連分析師風險清單都還沒進入。

短期不需要調整任何持倉。但有一件事值得記住：

**Transformer 論文的原作者之一，正在認真地說 Transformer 的記憶體架構走錯了。這不是雜訊。**
