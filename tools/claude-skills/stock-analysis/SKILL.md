## 模式偵測邏輯

```
收到指令
  ↓
標的是台股代號 / 台股技術關鍵詞？
  → 是 → 【台股模式】六模組 瓶頸→溢出
  → 否（美股 ticker）
      ↓
  說了「深度」「深挖」「深度分析」「深度報告」？
    → 是 → 【美股深度模式】六節原創洞察（先討論架構）
    → 否 → 【美股標準模式】七模組框架（直接執行）
```

## 【台股模式】六模組 瓶頸→溢出

**觸發：** 台股代號、CoWoS / HBM / SiC / CoPoS / 先進封裝等台股技術主題

### 核心方法論

```
瓶頸（現有技術物理 / 成本極限）
  ↓
需求溢出（新技術 / 替代路線）
  ↓
直接受益（第一層供應鏈台廠）
  ↓
間接受益（第二、三層）
  ↓
輸家（被替代者）
```

**判斷「現在在哪裡」：**
- 敘事期：技術未量產、無營收數字、股價反映預期
- 數字期：試產良率出爐、訂單確認、資本支出計畫明確

### 六模組結構

**模組 1：技術定位**
- 一句話說明「這是什麼」
- 為什麼「現在」重要（觸發點：競爭對手動作、物理極限、成本臨界）
- 與現有技術的關鍵差異表格（Callout type="data"）

**模組 2：供應鏈卡片**
- 三層結構：核心製造 / 設備材料 / 上游原材料
- 每個環節：台灣標的股票代號、角色說明
- 若台廠目前空缺某環節，必須標注

**模組 3：瓶頸→溢出分析（核心）**
- 現有技術的瓶頸是什麼（物理限制、良率問題、成本障礙）
- 量化瓶頸：具體數字（面積利用率、良率、成本差距）
- 溢出方向：條列誰受益、誰受壓
- Callout type="warning" 框出瓶頸
- 結尾量化換算（例：面積利用率差 X% = 有效產出差 Y%）

**模組 4：現在在哪裡**
- 明確標注：敘事期 / 數字期
- 時間軸：試產 → 量產 → 主流
- 投資含義
- Callout type="insight"

**模組 5：關注清單**
- 3–5 個具體可觀察的檢查點（法說、技術論文、月營收）

**模組 6：誰是輸家**
- 被替代的現有技術供應商
- 無法升級的傳統環節
- 供應鏈外流的台廠空缺
- Callout type="warning" 表格

## 【美股標準模式】七模組框架

**觸發：** 美股 ticker + 「分析」「寫文章」「產業分析」→ 直接執行，不討論架構

台股連動為**加分項目**：有明確台灣供應鏈就寫模組 5；無則省略，不影響文章產出。

### 七模組結構

**模組 1：公司定位**
- 一句話說明「這家公司做什麼」「市值 / 營收規模」
- 為什麼「現在」值得分析
- 與競爭對手的差異表格（Callout type="data"）

**模組 2：財務快照**
- 最新季度營收、毛利率、EPS vs 預期
- 下季度指引
- 本益比、PEG、自由現金流
- Callout type="data" 表格

**模組 3：核心護城河**
- 技術壁壘（專利、製程、生態系、網路效應）
- 量化：市占率、客戶黏性、毛利率相對同業
- Callout type="insight"

**模組 4：瓶頸→溢出（核心）**
- 現有技術 / 市場的瓶頸
- 溢出方向：誰受益、誰受壓
- Callout type="warning" 框出瓶頸

**模組 5：台股連動（加分項，非必填）**
- 有台股連動才寫；無則整個模組省略
- 直接供應商：台股代號、供應比重、受益程度（高/中/低）
- Callout type="data" 表格

**模組 6：催化劑與時程**
- 未來 3–6 個月具體催化劑
- 時間軸表格：時間 | 事件 | 對股價影響方向
- Callout type="insight"

**模組 7：風險與輸家**
- 1–3 個下行風險（量化影響幅度）
- 被替代的競爭對手或舊供應鏈
- Callout type="warning"

## 【美股深度模式】六節原創洞察

**觸發：** 美股 ticker + 「深度分析」「深挖」「深度報告」

**關鍵規則：步驟 2 使用者未確認架構前，不動筆寫文章。**

### 執行流程

```
收到指令
  ↓
步驟 1：快速 scan（3–5 次搜尋）
  → 公司基本面是否有足夠數據
  → 有沒有 3 個「非顯而易見」的洞察角度
  ↓
步驟 2：提出架構草案，與使用者討論
  → 說明各節內容方向
  → 提出第 5 節三個洞察角度，讓使用者確認或修改
  ↓
步驟 3：使用者確認後，並行搜尋各節數據
  ↓
步驟 4：撰寫全文
  ↓
步驟 5：寫檔 + git push
```

### 六節架構

**第 1 節｜業務本質**
- 技術或商業機制說明（不是官方說法改寫）
- 必須包含能力邊界表格：✅ 能做 / ❌ 不能做
- 讀者看完能向別人解釋技術原理

**第 2 節｜市場：供給 + 需求**
- 需求端：TAM / SAM、成長驅動因子（2–3 個）、CAGR
- 供給端：競爭者比較表（Callout type="data"），分析真實能力差距
- 沒有數字的地方寫「目前未取得可驗證數字」，不硬填

**第 3 節｜護城河**
每個護城河必須說明：
1. 物理或制度機制
2. 複製需要多少時間和金錢
3. 競爭者距離這個壁壘有多遠

Callout type="insight" 框出核心壁壘洞察。

**第 4 節｜財務軌跡**
- 一律表格，至少 2–3 年度對比
- 必填：年度營收 + YoY、毛利率、淨利、訂單積壓（若有）、關鍵業務指標
- 財務品質分析：說明數字背後品質（覆蓋率、收入結構、毛利趨勢）

**第 5 節｜結構性趨勢：三個被市場低估的洞察（核心）**
- 跨域連結：軍事 × 商業 / 法規 × 市場 / 地緣 × 供應鏈 / 科技演進 × 基礎設施淘汰
- 每個洞察：① 是什麼趨勢（數字錨點）② 為何市場未充分定價 ③ 對公司的直接影響
- **規則：若一個趨勢在公司 IR 簡報裡已提過，它就不夠深**

**第 6 節｜風險**
- 最多 3 個風險，每個必須含：機制 / 量化影響 / 減緩因子
- Callout type="warning"

**結語（必填）：**
1. 市場現在定價的是什麼
2. 市場沒有定價的是什麼（呼應第 5 節）
3. Callout type="quote" 一句話核心洞見

## 共用寫作規則

**Callout type（只有這五種，禁用 info）：**
| type | 用途 |
|---|---|
| data | 財務數據、供應鏈表格、競爭者比較、時間軸 |
| insight | 護城河、正面催化劑、受益邏輯 |
| warning | 風險、瓶頸、輸家、值得注意 |
| quote | 一句話結論 / 核心洞見 |
| link | 外部參考 |

**MDX 第一行（必填）：**
```
import Callout from '@components/Callout.astro';
```

**所有財務數字必須透過搜尋取得，不使用訓練資料中的財務數字。**
數據優先順序：官方 IR / SEC 申報 > 財經媒體 > 分析師報告 > 市場研究報告
